# BuildGuard API reference

`local BG = require(game.ServerStorage.BuildGuard)`

## Checking and fixing

| Call | Does |
|---|---|
| `BG.check(root, options?)` | Report and fix preview as a string. Changes nothing. |
| `BG.scan(root, options?)` | Returns `report`: `report.issues`, `report.counts.error/warning`, `report.partCount`, `report.overrides`, `report.timings` (`{ name, seconds }` per check, and one for `unclassified`), `report.coverage` (`meshTriangles`, `meshBoxOnly`, `reasons`, and `notes`: part path → note), `report.unclassified` (the road-like slabs no check treats as roads, in scan order; see How parts are classified). `root` can be an Instance or a list. Options: `config` (defaults for this call; `BuildGuard_` attributes still win), `yield = false` (never pause), `onProgress(stage, done, total, check, checks)`: check number `check` of `checks` (named `stage`) is running and has worked through `done` of `total` parts (0 of 0 when it doesn't count them; only `zfight` does). Each check's start comes as `(name, 0, 0)` and the end as `("done", 0, 0)`. |
| `BG.startCheck(root, options?)` | Starts `BG.check` in the background for a big area and returns a job id at once. |
| `BG.jobStatus(id, options?)` | `text, state`. While `"running"`: `BuildGuard check <id> running: zfight 1200/5000 parts (check 3 of 4, 12.3s so far)`. When `"done"` (or `"failed"`): the full report and fix preview, a page at a time with `{ page = n }` (120 lines per page; each page but the last ends `(page n of m; ask for page = n+1 for more)`, the last `(page m of m, the last page)`). The last 5 jobs are kept; read them only through `BG.jobStatus`. |
| `BG.format(report)` | Report as a string: the `Meshes:` line, `[NOTE]` lines, overrides, issues, time per check. When `report.unclassified` isn't empty, one `[NOTE]` line lists them: `[NOTE] 3 flat slab(s) look like road surfaces (Pebble, Asphalt) but aren't checked as roads: Map/Lookout_Yard, Map/Shoulder#1, Map/Shoulder#2 — name or tag them Road/Rail/Track (or set BuildGuardKind), or set BuildGuardKind = "None" on them or their folder if they aren't roads` (materials most common first; past 10 slabs it names the first 10 and adds `(first 10)`). |
| `BG.planFixes(report)` | Returns `plan, unfixedIssues`. Nothing moves yet. |
| `BG.Plan.describe(plan)` | Plan preview as a string. |
| `BG.apply(plan, name?)` | Applies as one undo step. Errors (`plan is stale, ... changed since it was made; scan again`) if any part changed since the scan the plan was made from. |
| `BG.revert(plan, name?)` | Puts everything back. |
| `BG.fixAll(root, options?)` | Scan, plan, apply, repeated until nothing more is fixable (`maxPasses`, default 4). Returns `{ report, plans, changes }`. |
| `BG.formatChanges(resultOrPlan)` | The fix report: every changed part (by path) with its exact move in world and own axes, its resize, and the line to put in its builder script. |
| `BG.changes(resultOrPlan)` | The same as a list: `{ part, path, move, moveLocal, resize, rotated, fromCFrame, toCFrame, fromSize, toSize, checks, reasons }`. |
| `BG.find(root, path)` | The instance a report path names (`"Map/Tub/TubTop#3"`; the first segment is `root`'s own name), or nil. |
| `BG.planSnap(partsOrModel)` | Snap plan: for a model or folder, its roads/rails/tracks; for a list, every listed part. Ignored parts (`BuildGuardIgnore`) and parts of a vehicle are never moved. Returns `plan, skipped` (`{ part, reason }` for ramps, parts with no ground or buried too deep, and ignored or vehicle parts). |
| `BG.Layers.place(item, surface, opts)` | Puts an item on a face and returns it. Options: `face` (default `"Top"`), `layer` (default 1; 0 rests the item flush on the face), `u`, `v`, `rotation`, `keepPosition`, `config`. Not for a WedgePart's slope. |
| `BG.Layers.lift(layer, config?)` | Studs above the surface for that layer (0 for layer 0). Errors unless `layer` is a whole number >= 0. |
| `BG.setConfig(instance, { key = value }, reason)` | Sets overrides for an instance and everything under it. Validated; reason required. One undo step. |
| `BG.setProjectConfig({ key = value }, reason)` | Place-wide settings (on `workspace`); they also reach models outside workspace. |
| `BG.clearConfig(instance, keys?)` | Removes the listed overrides, or all of them. |
| `BG.getConfig(instance?, options?)` | Returns `config, sources` (`sources[key]` = the instance that set it). `nil` gives the place-wide config. |
| `BG.explainConfig(instance)` | Every setting for the instance and where it comes from, as text. |
| `BG.snapToGrid(cframeOrVector, relativeTo?)` | Rounds X/Z to `gridSize` (`relativeTo`'s config, else the place-wide one). Keeps height and rotation. |
| `BG.withUndo(name, fn, discard?)` | Runs `fn` as one undo step and returns what it returns. `discard = true` rolls all of `fn`'s changes back even when it succeeds. |
| `BG.checkVehicle(model, target?)` | Measures an (imported) vehicle and compares it with the limits for `target` (default workspace), to set road numbers. Returns `text, rows, profile`; each row is ok/check/fail. |
| `BG.measureVehicle(model)` | Width, height, length, wheel radius, wheelbase, clearance, approach/departure/breakover angles (from part boxes). |
| `BG.vehicleLimits(profile)` | `{ maxLedge, maxSlopeChange, minRoadWidth, roadHeadroom }` that vehicle needs. |
| `BG.selfTest(options?)` | Builds the planted-problem scene at `options.origin` (default (-24576, 0, 24576)) from the settings at `options.parent` (default workspace), waits up to 5 s for its new terrain to show up in raycasts, checks and fixes it, and removes it. Returns `{ passed, text, rows }`. It runs as one undo recording that is cancelled at the end, so it leaves no undo steps; `{ keep = true }` keeps the scene as one undo step. It sets its terrain back to Air afterwards, so it only builds on an empty spot: if any part, terrain or water is in the scene's box plus 8 studs, it builds nothing and returns `{ passed = false, refused = true, rows = {}, text }`, the text starting `BuildGuard self-test: not run, nothing was built. <what> is in the test scene's area at (x, y, z), the box from (...) to (...).` and ending with `pick one and pass it, e.g. BG.selfTest({ origin = Vector3.new(x, 0, z) })`. If the terrain doesn't show up in time, nothing is scanned and its one row is `terrain    new terrain wasn't visible to raycasts after 5 s, so nothing was scanned: P5, P13 and P14 need it. Run the self-test again`: run it again. A call that can't wait (it can't yield) scans at once, and its text ends with `  note  this call couldn't wait for the new terrain to show up in raycasts, so it scanned at once: if P5, P13 or P14 fail, run the self-test from the command bar or the plugin's Run self-test button`. |
| `BG.TestScene.buildFarView(parent, origin?, world?)` | Builds the far-view rig at `origin` (default (-24576, 0, -24576)): plate pairs with gaps 0.005–0.2 and spawn pads `View_100`, `View_300`, `View_600`. Publish to a test place and join on a phone (players spawn on the pads; disable the map's own SpawnLocations, or reset to land on another pad) to see which gap stops flickering. Delete it afterwards. It only builds on an empty spot: if any part, terrain or water is in its box plus 8 studs, it errors without building anything: `BuildGuard: far-view rig not built: <what> is in its area at (x, y, z), the box from (...) to (...). Build it on an empty spot: BG.FarView.build(workspace, Vector3.new(x, 0, z))`. `BG.FarView.build` is the same function. |

Every issue has `check`, `severity`, `message`, `parts`, `paths` (each part's path from the scan root; `#n` marks the nth of several siblings with the same name; `%` and `/` in names are written `%25` and `%2F`) and, when it applies, `position` (where to look). A `gap` issue also has `value` (the gap in studs) and `edge` (`+X`, `-X`, `+Z` or `-Z`, by the part's own axes). `zfight`, `zgap` and `zseam` issues have `width`: the widest overlap between flat part faces in the pair (nil when they only meet on round surfaces or mesh triangles).

## Checks

| Check | Severity | Meaning | Auto-fix |
|---|---|---|---|
| `config` | error | A `BuildGuard_` attribute is invalid (a `zFightNudge` not above 0.01 is dropped on its own); it's ignored | Fix or clear the attribute |
| `duplicate` | error | Two parts of the same class, mesh (or shape) and look (colour, material, transparency, texture) at the same position, rotation and size (a double import) | Manual: delete one |
| `buried` | error | Something covers a road/rail/track's driving surface | Snap onto the ground if the cover is terrain or ground. Otherwise manual. |
| `offground` | warning | A flat road/rail/track hovers or is sunk more than `groundTolerance` (0.1), or has no ground below it | Snap to ground (none when there's no ground) |
| `zfight` | error | Same-facing faces overlap within 0.01 studs: flat faces, the round sides of same-size cylinders on one axis, same-size balls on one centre, and mesh triangles (meshes the place can load). Overlaps under 0.01 studs² or thinner than about 0.001 studs (rounding where pieces meet edge to edge) don't count. Nor does a flat overlap that faces of third parts cover all over, back to back: each cover points the other way, lies in the overlap's plane within `zFightTolerance` and belongs to a part below `zFightIgnoreTransparency` (meshes, unions and parts drawn by a mesh never cover). So a footing's top flush with the ground pad or level land facet it passes through, both under the road, is clean, and two overlapping layer-0 items never fight on their bottoms (on a surface that shows). An overlap only partly covered is reported with its whole area. The message ends with the widest flat overlap's width: `... overlap 25.60 studs², a strip 0.050 wide` (a strip is at least four times as long as it is wide) or `... overlap 4.00 studs², 2.00 wide`; pairs meeting only on round surfaces or mesh triangles give no width. | Nudge the smaller part out (round parts grow their radius instead). When a third part that shows hides its other side on that axis (a layer-0 item's bottom on the road), it sinks into that part by the nudge instead, so no light opens under it, but only when its far face stays more than `zFightTolerance` + 0.005 clear of that surface and none of its faces would end flush on one of that part's. Otherwise (a marking no thicker than the nudge + 0.015, a rib across a road's full width) it lifts by the nudge. It grows instead only when it fights on both opposite sides and neither is hidden. Welds/Motor6Ds on moved parts are updated. When both parts are locked or ground: manual, and the message says so. |
| `zgap` | warning | In a model with `zFightViewDistance`, same-facing faces closer than the gap that holds at that distance. Only beyond about 130 studs, where that gap is more than `zFightNudge`. | Move to that gap, keeping the face in front in front (push the back one further back, shrink an inner ball or rod) |
| `zseam` | warning | Every overlap between flat part faces in the pair is narrower than `zFightSeamWidth` (0.03) and at most half as wide as either face: pieces laid edge to edge that overlap by a hair, often land facets from a generator. Barely visible. A thin part sunk flush in a face (an inlay, a wire) is all overlap, so it's a `zfight`. `Map/Land/Facet#12 and Map/Land/Facet#13 overlap in a strip 0.012 studs wide along their shared edge (Right/Left faces, 0.35 studs²) at (x, y, z): barely visible; pull the pieces apart in their plane (often a generator overlapping pieces by a hair)`. Mesh triangles are never seams. | Manual: pull the pieces apart in their plane, or leave it and tell the user. Not nudged: a nudge would leave a step between pieces meant to be flush. |
| `meshoverlap` | warning | Two meshes/unions whose boxes nearly coincide (a double import or a z-fighting copy) | Manual: check by eye |
| `headroom` | warning | Less clear height above a road/rail/track than its kind's headroom setting: a tunnel roof, bridge, overhang or a road deck crossing above | Manual |
| `ledge` | warning | Step between connected roads (or rails) over `maxLedge` | Manual |
| `edge` | warning | Step from the ground beside a road up onto (or down off) its edge over `maxLedge` | Manual: thinner road, or shape the ground up to it |
| `gap` | warning | A flat road/rail/track resting on the ground (not buried, not off it) has a gap under its edges over `maxHover` (0.25) plus its kind's lift if positive (rails: 0.25 + 0.2). It's the biggest gap between the face it rests on and what shows below, within max(2, `sampleSpacing`) studs of that face's edges. What shows is the snap's ground: terrain, ground parts and any part starting below the road's bottom, so a footing counts; parts resting on the road, layered items, other pieces of the same kind, ignored parts and vehicles don't. But light passes through invisible parts (Transparency at or above `zFightIgnoreTransparency`, 0.99), so an invisible footing doesn't close the gap, and over water the gap ends at the water's surface. Where an edge passes over a drop deeper than `connectMaxStep` (4), or over nothing, that stretch is a span and doesn't count, nor do the samples either side of it out to the first one back within the limit (the banks sloping into a ravine). The rest of that edge, and the other edges, still count. `Road Map/Roads/Road_West_2 has a 1.21-stud gap under its -Z edge at (x, y, z) (limit 0.25): sink it into the ground (negative roadLift), put a footing under it, or raise the ground there`. The limit shows `+ railLift 0.20` for rails and `, set on <path>` when a model sets `maxHover`; for rails the advice is `put a footing under it or raise the ground there`. Over water it reads `has a 2.00-stud gap above the water under its +Z edge`. Through an invisible part: `... (limit 0.25) that shows through invisible Map/Roads/Footing_Road_West_2: make it opaque (Transparency under 0.99) so it fills the gap, sink the road into the ground (negative roadLift), or raise the ground there` (for rails: `make it opaque (Transparency under 0.99) so it fills the gap, or raise the ground there`). Edge warnings still apply to the same road. | Manual: a footing under it (keeps its top where it is), a negative lift, or raise the ground |
| `slope` | warning | Angle between connected roads (or rails) over `maxSlopeChange` | Manual |
| `routeslope` | warning | A road or rail piece's driving surface tilts more than `maxRouteSlope` (a wedge ramp by its slope) | Manual |
| `roadwidth` | warning | A road is narrower than `minRoadWidth` across its driving direction | Manual |

The report's `Meshes:` line says how many meshes were checked by their triangles and how many by their box only, and why (no permission to load the mesh, unions, drawn by a SpecialMesh, BlockMesh or CylinderMesh child, too many triangles). A box-only mesh is **not checked for z-fighting** at all, only for duplicates and overlapping boxes: check it by eye. A `[NOTE]` line under it is something the scan noticed about a mesh (its data isn't centred on its bounds, so its box doesn't match what you see).

## Settings you can override per model

Set with `BG.setConfig` (or `BG.setProjectConfig` for the whole place), stored as `BuildGuard_<key>` attributes. They win over a call's `config` options. Checks that compare two parts (joins, z-fighting pairs) use the settings of the smallest instance holding both. Z-fighting detection (`zFightTolerance` 0.01, `zFightMinOverlapArea` 0.01, `zFightSeamWidth` 0.03, `zFightIgnoreTransparency` 0.99) can't be set per model, only in a call's `config` options or `Config.lua`. `zFightSeamWidth` (0–0.2, 0 = off; a value outside that errors: `zFightSeamWidth must be between 0 and 0.2, got 0.5`): a pair whose flat faces only overlap in strips narrower than this, each at most half as wide as either face, is a `zseam` warning instead of a z-fight. `zFightIgnoreTransparency`: parts at or above it aren't scanned for z-fighting, don't cover a contact or hide a mover's side, and are looked through by the gap check.

| Key | Default | Range | Meaning |
|---|---|---|---|
| `zFightNudge` | 0.02 | 0.002–0.5 | Gap a z-fight fix leaves; must be > 0.01 |
| `zFightViewDistance` | 0 (off) | 0–5000 | Distance the model is seen from. Faces must be `2 × d² / (0.1 × 2²⁴)` apart (0.107 at 300 studs; never less than `zFightNudge`), fixes leave that gap, and layers lift at least that much. Under about 130 studs it adds nothing. For map-sized models seen from far away on phones. |
| `layerLift` | 0.05 | 0.002–0.5 | Lift per layer (read from the surface) |
| `roadLift` / `trackLift` | 0 / 0 | −2–2 | Where a snap puts the bottom of roads / track beds, from the highest ground under them: 0 rests them on it, negative sinks them in. They only sink into terrain or ground parts (never into a support, and wedges never sink), and their top always stays 0.05 above the ground. |
| `railLift` | 0.2 | 0–2 | Gap a snap leaves under rails (room for sleepers) |
| `groundLift` | 0 | −2–2 | Like `roadLift`, for anything else you snap |
| `gridSize` | 4 | 0.05–512 | Horizontal layout grid for `snapToGrid` |
| `groundTolerance` | 0.1 | 0.01–10 | Off-ground check fires beyond this |
| `maxHover` | 0.25 | 0–10 | Biggest gap allowed under the edges of a flat road/rail/track resting on the ground (`gap`), on top of its kind's lift if positive. Set it on a low bridge's model (a deck less than `connectMaxStep` above what's under it, water included). |
| `flatTiltDegrees` | 5 | 0–45 | Steeper parts count as ramps |
| `snapSearchUp` / `snapSearchDown` | 20 / 500 | 0–1000 / 1–10000 | How far a buried part looks up for open air / how far snapping looks down |
| `buriedProbeHeight` | 0.25 | 0.01–10 | Cover must rise this far above the surface |
| `buriedClearance` | 3 | 0.1–100 | How far overhead counts as covering |
| `roadHeadroom` / `railHeadroom` / `trackHeadroom` | 0 (off) | 0–500 | Clear height needed above each kind. Set `roadHeadroom` place-wide from the truck (`checkVehicle` suggests it). |
| `sampleSpacing` | 2 | 0.25–50 | Sample grid spacing for buried/snap/edges |
| `maxLedge` | 1.0 | 0–50 | Step between connected roads/rails, and from the ground onto a road edge |
| `maxSlopeChange` | 20 | 0–90 | Angle between connected roads/rails |
| `maxRouteSlope` | 20 | 0–90 | Steepest tilt of any road/rail piece |
| `minRoadWidth` | 22 | 0–1000 | Road width across the driving direction (the approved haul road) |
| `edgeProbe` | 0.5 | 0.05–4 | How far outside a road edge the ground is measured |
| `connectMargin` | 0.1 | 0–5 | Horizontal gap still counted as connected. Joins use this or `edgeProbe`, whichever is larger (0.5 by default), so a gap the edge probe steps over is checked as a join. |
| `connectMaxStep` | 4 | 0.1–100 | Bigger vertical gaps are overpasses (and drop-offs at road edges, and spans under a road's edge for the gap check) |

Global settings (call options or `Config.lua` only): `classifyByName` (true), `kindNameWords`, `kindMaxThickness` (0.5), `drivableKinds` ({"Road", "Rail"}), `edgeLedgeKinds` ({"Road"}), `groundNames`, `groundMinFootprint` (0 = off), `meshTriangles` (true), `meshTriangleLimit` (20000), `meshOverlapRatio` (0.9), `roadLikeMaterials` ({"Asphalt", "Concrete", "Pavement", "Pebble", "Cobblestone", "Slate", "Ground", "Mud", "Sand"}: `Enum.Material` names of the slabs listed in `report.unclassified`).

## How parts are classified

- **Road / Rail / Track:** the `BuildGuardKind` attribute (`"Road"`, `"Rail"`, `"Track"` or `"None"`), then a tag `Road`/`Rail`/`Track`, then the name. By name, its **first word** is road/roads/roadway/street/highway (Road), rail/rails/railroad/railway (Rail) or track/tracks/trackbed (Track), and the part:
  - is flat: no thicker than half its longest side, and not a panel standing on edge (taller than its shorter side and over 1 stud tall; rails under a stud tall are fine);
  - has its top within 45° of level (a block or mesh may be upside down; a WedgePart's slope must face up);
  - isn't a ball, cylinder or corner wedge, and wasn't placed with `Layers.place`;
  - is at least 4 studs across its shorter side, for a road;
  - isn't part of a vehicle.

  Words split at capitals, digits and punctuation, so `Road_01`, `RailYard` and `TrackBed` count; `BedRail`, `RoofRail`, `Railing`, `StreetLamp` (a pole), `RoadSign` (any shape, on a post, a wall or placed with Layers), `Highway_Exit` signs, `Road_Guardrail`, `RoadBarrier`, `RailFence`, `StreetLight` heads, `Road_Kerb` strips and layered `RoadLine` markings don't. Tags and `BuildGuardKind` win whatever the shape or tilt: a ramp steeper than 45° counts only when tagged or marked.
- **Road-like slabs (`report.unclassified`):** a part with no kind, made of a material in `roadLikeMaterials`, that's a slab to drive on. It's listed so roads nobody named (yards, shoulders, turnarounds) aren't skipped silently. Its shape:
  - flat by the name rules, not a ball, cylinder or corner wedge, and not layered;
  - its top within 10° of level (`Classify.NOTE_MAX_TILT`): an upside-down block counts, a wedge counts by its slope, so pitched roofs and steep wedge ramps don't;
  - at least 1.5 studs across its shorter side and 6 along its longer (`NOTE_MIN_WIDTH`, `NOTE_MIN_LENGTH`);
  - under 4 studs across (`ROAD_MIN_WIDTH`), a strip to drive along, at least 12 long and 6 times longer than wide (`NOTE_STRIP_LENGTH`, `NOTE_STRIP_RATIO`: a shoulder, a lane), or named like a road (first word in `kindNameWords`, such as a too-narrow `Road_Shoulder`). Steps, lintels, shelves, planks and short wall caps aren't listed.

  Left off: ground parts, ignored parts, vehicle parts, anything at or under an instance with `BuildGuardKind = "None"`, and slabs the roads, rails or tracks resting on them cover (footings, plinths). A road rests on a slab when its bottom is within 0.5 studs of the slab's top plus its kind's lift if positive (`roadLift`, `railLift`, `trackLift`), or it's sunk into it. They cover it when the slab lies within one such road's footprint plus 1 stud (`FOOTING_MARGIN`), or its top is at most 1.2 times the area they cover together (`FOOTING_COVER`; a footing under two road pieces meeting over it). A yard or turnaround a road runs onto and stops in, or a bed much wider than its road, is still listed. Finding them costs no raycasts.
- **Driving surface:** the face that's up: Top, the Bottom of a block or mesh lying upside down, or a WedgePart's slope (a wedge ramp's foot is at ground level, so it has no edge step there). Snapping and `offground` use the face the part rests on (a wedge's flat bottom, an upside-down block's Top), and a snap keeps the rotation.
- **Ground:** Terrain, the `BuildGuardGround` tag or attribute (on the part or any ancestor; the nearest one wins, so tag a floor folder once and set `BuildGuardGround = false` on anything in it that isn't ground), or a flat part whose first word is `Baseplate`/`Ground`/`Terrain`. Size alone doesn't make a part ground, so tag big floors that are ground.
- **Ceilings (headroom):** anything above the probe, including a road, rail or track deck crossing over. Junction pieces overlapping the road, rails resting on their bed, layered items, ignored things and vehicles are never ceilings.
- **Wheels:** the `BuildGuardWheel` attribute or tag; else parts that spin on a HingeConstraint or CylindricalConstraint through their centre along their round axis; else (only when nothing spins) names whose first word is wheel/tire/tyre followed only by position words (`Wheel_FL`, `TireRearLeft`). Used by `checkVehicle`; a steering wheel, spare wheel or wheel arch is never a wheel.
- **Vehicles** are modelled in Blender and kept separate: keep them out of the models you check and fix, or tag them `BuildGuardIgnore` (fixes don't skip vehicle parts). Parts BuildGuard sees as a vehicle's (everything joined to a VehicleSeat or to two or more spinning wheels, plus every part of a model holding a VehicleSeat or marked `BuildGuardVehicle`) never count as roads by name, cover, ground or a ceiling, and are never snapped.

## Attributes and tags

| Attribute / tag | Effect |
|---|---|
| `BuildGuardKind` = `"Road"` / `"Rail"` / `"Track"` / `"None"` (on the part) | Sets or clears the kind (overrides tags and the name) |
| `BuildGuardKind = "None"` (on a folder or model) | Leaves everything under it off the road-like slab note. It only silences the note: roads inside still count by name or tag. |
| tag `Road` / `Rail` / `Track` (on the part) | Sets the kind |
| `BuildGuardGround` (attribute true/false or tag) | It and everything under it count as ground (or, with false, don't); the nearest one wins |
| `BuildGuardLocked = true` (on the part) | Fixes never move it (also true for `Locked` parts and ground). A z-fight between two such parts, or a locked road that's buried or off the ground, isn't auto-fixable; `planSnap` skips it. |
| `BuildGuardIgnore` (attribute true or tag) | It and its descendants are skipped, never snapped, and never count as cover, ground or a ceiling |
| `BuildGuardLayer` | Set by `Layers.place` to the layer (0 for a flush item). Marks layered items: never roads by name, cover or ceilings; they ride along when the part under them is snapped. |
| `BuildGuardWheel` (attribute true/false or tag) | Marks (or unmarks) a part as a wheel for `checkVehicle` |
| `BuildGuardVehicle` (attribute true or tag) | Marks a model as a vehicle |
| `BuildGuard_<key>` | A config override (see above) |
| `BuildGuardConfigReason` | Why the overrides on this instance exist (set by `setConfig`) |

## Lower-level pieces

Used by the checks and the self-test; a build rarely needs them.

- `BG.Classify.unclassified(ctx)`: the road-like slabs for a context (`ctx = BG.newContext(root, options)`). `BG.Classify.describeUnclassified(parts, pathOf)`: the `[NOTE]` text, naming the first `BG.Classify.UNCLASSIFIED_SHOWN` (10). `BG.Classify.optedOut(instance, cache?)`: true at or under `BuildGuardKind = "None"`. The slab rules' numbers are module constants, not settings: `NOTE_MIN_WIDTH` (1.5), `NOTE_MIN_LENGTH` (6), `NOTE_STRIP_LENGTH` (12), `NOTE_STRIP_RATIO` (6), `NOTE_MAX_TILT` (10), `FOOTING_MARGIN` (1), `FOOTING_COVER` (1.2), `ROAD_MIN_WIDTH` (4). `BG.Classify.LIFT_KEY` (also `Ground.LIFT_KEY`): `{ Road = "roadLift", Rail = "railLift", Track = "trackLift" }`, the setting each kind's lift comes from.
- `Ground.measure(solid, ctx)` (module `Checks.Ground`): `{ delta, samples, groundY, starts, hits, waterY }` (`samples` on the face the part rests on, `groundY[i]` the ground height under `samples[i]`, nil where none was found; `starts[i]` where its ray started, nil where buried; `hits[i]` the ground it hit; `waterY[i]` the height of a water surface above that ground), or `{ skip = reason }`. Water never holds a part up: the snap and `offground` measure to the ground under it. `Ground.edgeGap(solid, measure, config, ctx?)`: `{ gap, position, edge, water, through }` for the biggest gap near the edges, or nil. With `ctx` (as the gap check calls it) it measures to what shows: `water` is true when that's a water surface, `through` is the invisible part looked through, and a sample with nothing below it is part of a span. Without `ctx` it measures to the snap's ground.
- `BG.Geometry.polygonWidth(poly)`: a convex polygon's thinnest extent. `BG.Geometry.coplanarOverlap(fa, fb, tolerance, minArea)` returns `area, distance, centroid, width`. `BG.Geometry.overlapCover(fa, fb, covers)` returns `coveredArea, overlapArea`: how much of the overlap of same-facing faces `fa` and `fb` the faces in `covers` (pointing the other way, back to back on it) hide, each grown by the float rounding `coplanarOverlap` ignores. Covers that overlap each other count twice; the sum is capped at the overlap (`0, 0` when there's no overlap).
- `SelfTest.areaProblem(world, config, origin)` (module `SelfTest`): nil when the test scene's spot is empty, else `<what> is in the test scene's area at (x, y, z), the box from (...) to (...)`. `BG.TestScene.bounds(config, origin)`: `cframe, size` of the scene's box plus 8 studs. `BG.TestScene.build` also returns `terrainProbes` (`{ origin, direction }` rays: down onto the hill, up into the tunnel roof).
- World adapters (`StudioWorld`, and the tests' `FakeWorld`): `world.waitForTerrain(probes, timeout?)` is `true` once every probe ray hits terrain, `false, "timeout"` after `timeout` (5 s), or `false, "cannot-yield"` when they miss and the call can't wait. `world.raycast(origin, direction, ignore?, includeWater?)` is `{ instance, position, normal, water? }` or nil: rays pass through water unless `includeWater` is true, and then can stop at its surface (Terrain, with `water = true`). `world.isAreaEmpty(cframe, size)` is `true`, or `false, what` (a part's full name, or `terrain (Material) at (x, y, z)`). In Studio: `require(game.ServerStorage.BuildGuard.StudioWorld).new()`.
